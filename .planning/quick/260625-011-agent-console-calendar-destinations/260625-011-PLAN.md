# 260625-011 Agent Console Calendar And Destination Migration

## Goal

Finish the Agent Console migration layer requested by the user:

1. Move calendar scheduling configuration out of Settings and into Agent Console.
2. Keep the local scheduler daemon as the deterministic execution layer, but make Console the product owner of calendar accounts and watched calendars.
3. Hide legacy AI runtime / LLM / output settings from the visible settings surface.
4. Let Notion and Zulip destination rows keep the current "configured + target" UX, while supporting destination changes and Agent-sourced destination candidates.
5. Suppress local meeting citations for general Ask Meeting answers that do not cite numbered local sources.

## Assumptions

- Agent calendar context cannot replace the timer/recorder role of Yulu's local scheduler daemon today; it can replace the configuration entry point.
- Agent connector destination enumeration is best-effort because provider CLIs do not expose one stable JSON API. Yulu should support Agent-returned JSON candidates, cache them, and fall back to manual input.
- Internal config compatibility keys may stay in `config.json`; the user-facing settings entry points should disappear.

## Verification

- Focused router/web tests for Agent Console, ask, settings, and settings registry.
- `npm run typecheck`
- `npm run build`
- `make dev-install`
- `python3 yulu/scripts/doctor.py --json`

## Result

- Done: Calendar account/source selection moved into Agent Console, with local scheduler/calendar restart on save.
- Done: Legacy Settings AI runtime / LLM / output / integrations UI entries removed or redirected to Agent Console; internal config keys remain hidden for compatibility.
- Done: Notion and Zulip target dialogs now support changing saved targets and can refresh Agent-discovered destination candidates.
- Done: Ask Meeting local citations only render when the assistant answer cites numbered local sources.
- Kept by design: Yulu local scheduler remains the deterministic reminder/auto-record execution layer; Agent calendar context is the AI context/config layer, not the timer service.
