# 260625-008 Summary

## Implemented

- Expanded Agent runtime detection to include Codex, Claude Code, Hermes, and OpenClaw.
- Added user-local executable fallback paths such as `~/.local/bin`, so Hermes can be found when the UI process PATH is narrow.
- Made Hermes and OpenClaw selectable provider IDs in config/schema and Agent Console.
- Added provider-specific session command builders:
  - Codex: existing `codex exec ... resume <session>`
  - Claude: `claude --print ... --session-id <Yulu session UUID>`
  - Hermes: `hermes chat -Q --source yulu --query ...` plus `--resume <session>` when known
  - OpenClaw: `openclaw agent --json --session-id <Yulu session UUID> --message ...`
- Fixed Ask Meetings "New Chat" so it enters a draft state instead of auto-selecting the newest history session.
- Threaded the Yulu session ID into Agent CLI calls so ask/background sessions can anchor native provider sessions.
- Removed legacy Summary LLM runtime controls from Settings and replaced them with an Agent Console handoff.
- Removed the AI Integrations output section from Settings.
- Reworked the integrations calendar area as:
  - current Agent calendar context status
  - Yulu-owned native scheduler calendar source selection
- Kept auto-run summary template visibility in Settings because it belongs to prompt/template management rather than provider runtime credentials.

## Remaining Gaps

- Hermes native session id capture depends on Hermes printing a UUID in quiet output; if Hermes does not expose it for a first one-shot turn, subsequent resume cannot be guaranteed until we add a Hermes session-store lookup.
- OpenClaw execution is wired to `openclaw agent --json`; it still depends on the user's OpenClaw gateway/provider health.
- The Settings registry still contains legacy `llm.*` and `output.*` config definitions for backwards compatibility and migration safety, but the UI no longer exposes those controls.
