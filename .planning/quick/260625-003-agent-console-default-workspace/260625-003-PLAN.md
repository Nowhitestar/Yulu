# Quick Task 260625-003: Agent Console Default Workspace

## Goal

Implement Agent Console as Yulu's default workspace, using the provided Magic Patterns design code as interaction reference while keeping the existing Yulu visual language and backend boundaries.

## Assumptions

- Agent Console is an additive product surface over existing routers first; it should not replace the recording/STT/queue architecture.
- Recent task cards show recordings from the last three days and derive status from existing recording metadata, queue/share state, and recording daemon status.
- Ask Meetings moves out of GlobalSearch; GlobalSearch returns to search-only behavior.
- Agent configuration changes update Yulu's Agent runtime preference only; connector configuration remains owned by the selected Agent where possible.

## Tasks

1. Backend Agent Console surface
   - Add a focused tRPC router for Agent detection, Agent runtime switching, and recent task normalization.
   - Reuse existing recordings, ask, integrations, queue, doctor, scheduler, and config logic.
   - Verify with focused router tests.

2. Agent Console route
   - Add the default workspace route with left recent-task rail, center Ask/Run surface, and right Agent/capability/status rail.
   - Wire task actions to real mutations for recording, transcribe, summarize, and send.
   - Verify with focused web tests and typecheck.

3. Navigation and migration
   - Make Agent Console the default entry and add primary sidebar navigation.
   - Move AI-native controls conceptually into the Console and remove Ask mode from GlobalSearch.
   - Verify existing settings/search tests continue to cover legacy flows.

4. Validation
   - Run targeted router/web tests, `npm run typecheck`, and build if the focused suite passes.
   - Optionally run local dev install and doctor if the UI/server changes are stable.
