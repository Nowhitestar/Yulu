# Quick Task 260625-007: Provider-Native Agent Sessions

## Goal

Close the remaining Agent CLI migration gap by binding Yulu's persisted Agent
sessions to provider-native session/resume semantics where the CLI exposes them.

## Assumptions

- Local Codex CLI exposes `codex exec resume [SESSION_ID] [PROMPT]` and persists
  non-ephemeral `codex exec` sessions.
- Claude Code CLI is not installed on this machine, so this pass must keep a
  clean adapter seam and degrade to normal `claude --print` execution.
- Yulu should store the provider-native session id alongside its own session id.

## Plan

1. Add an Agent CLI session adapter.
   - Verify: tests cover Codex first-run command, Codex resume command, and
     unsupported provider fallback.

2. Persist native session ids on Yulu Agent sessions.
   - Verify: store tests cover setting a native id without losing messages.

3. Route background actions and Ask Meetings through the adapter.
   - Verify: recordings and ask router tests assert resume commands after native
     id is present.

4. Validate and smoke.
   - Verify: typecheck, focused tests, full Vitest, build, and browser smoke.

## Result

- Added `agentCliRunner`, a provider-native execution adapter.
- Codex runs now use `codex exec --json -o <last-message-file> -` for first calls.
- Codex runs with an existing native session use `codex exec ... resume <session-id> -`.
- Yulu Agent sessions now persist `nativeSessionId`.
- Background summary/share actions reuse the background session's native Codex id after the first call.
- Ask Meetings passes its Yulu session id to the server, and the server resumes that session's native Codex id when present.
- Claude/custom commands still use the previous plain command path until a native Claude resume adapter is available locally.
