# Quick Task 260625-005: Agent Console Sessions And Capability Boundary

## Goal

Make Agent Console behave more like the selected underlying Agent's workspace:

- Ask Meetings conversations persist as Agent-scoped sessions.
- Recent-three-day task cards use real generated artifacts as the source of truth, so a meeting with a summary moves to the share stage.
- The architecture is explicit about which AI capabilities Yulu owns and which should be delegated to the selected local Agent CLI and its connectors.

## Assumptions

- Yulu should keep capture, local files, STT, prompt/template data, vocabulary data, and search/retrieval.
- The selected Agent should own LLM execution and connector execution where possible.
- Existing legacy AI integration settings remain for compatibility, but Agent Console is the new product layer.
- Persistent Ask Meetings sessions can be stored in the Yulu runtime config directory as a small local JSON store before a broader SQLite migration is justified.

## Plan

1. Add persistent Agent sessions
   - Verify: router tests cover create/list/get/append and Agent filtering.

2. Wire Ask Meetings to persisted sessions
   - Verify: UI test covers loading prior messages and appending a new answer.

3. Fix recent task state derivation
   - Verify: router test covers a meeting with transcript, summary, and a newer in-progress/stale state still rendering as ready to share.

4. Document the Agent capability boundary
   - Verify: architecture note explains current implementation and the intended CLI delegation path for LLMs/connectors.

5. Validate locally
   - Verify: typecheck, focused tests, build, and Agent Console browser smoke on the local preview.
