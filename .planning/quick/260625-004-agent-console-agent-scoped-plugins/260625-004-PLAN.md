# Quick Task 260625-004: Agent Console Agent-Scoped Plugins

## Goal

Correct Agent Console architecture and UI so the Console behaves as the Agent-native control layer:

- Meeting detail should not duplicate local system status.
- Recent-three-day cards should show one current actionable state, not four static stage dots.
- Current capabilities should follow the selected underlying Agent.
- Console plugin visibility is a Yulu-side filter over the selected Agent's capabilities.
- Configure actions should route through the selected Agent boundary instead of legacy Yulu AI integration setup.
- Meeting Q&A responses should render Markdown.

## Assumptions

- The legacy AI integration settings remain in the codebase for compatibility, but Agent Console should stop depending on them as the product source of truth.
- The first supported plugin layer should cover the user-named capabilities: Notion, Zulip, Calendar, and Summary.
- A plugin can be available in Yulu, hidden until added in Console, added-but-unconfigured in the selected Agent, or configured in the selected Agent.
- Codex and Claude are active Agent targets; Hermes and OpenClaw stay discoverable/visible but disabled until their contracts exist.

## Plan

1. Inspect current code and design reference
   - Verify: identify current detail status component, recent task card rendering, capability status source, and Markdown response path.

2. Add Agent-scoped plugin model
   - Verify: router tests cover selected Agent changes causing plugin states to change.

3. Update Console UI behavior
   - Verify: web tests cover single-state task cards, add/remove plugin filter, configured/unconfigured colors, and Markdown rendering.

   - Verify: typecheck, focused tests, build, local Agent Console smoke.
