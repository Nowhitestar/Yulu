<objective>
Generalize the proven `ClaudeCodeProvider` capability-provider to **Codex** and **OpenClaw**, completing the multi-agent-from-v1 lock so Yulu is agent-native, not single-vendor. This is the FINAL milestone phase and is **pure addition**: two new `CapabilityProvider` subclasses + two `default_providers()` entries, mirroring the reference implementation against an already-locked interface.

Closes AGENT-01 (CodexProvider) and AGENT-02 (OpenClawProvider).

Phase 3 designed `capabilities/provider.py` so a second/third agent is a drop-in (D-06): the `CapabilityProvider` ABC carries no agent-specific vocabulary and `default_providers()` is the single extension point. This plan proves that design holds by adding two real agents with ZERO edits to `report.py` or `probes.py`, and ZERO edits to `doctor.py` (the existing fold already iterates `default_providers()`).

**One real collision to handle (D-03):** the doctor fold merges provider entries with `report.capabilities[name] = cap` (verbatim key, last-writer-wins — confirmed at `doctor.py:271-272`). `ClaudeCodeProvider` emits `agent_mlx_whisper`; if Codex and OpenClaw also emit the bare `agent_mlx_whisper`, all three clobber to one entry. The fix is provider-side, not doctor-side: the NEW providers namespace their mlx-whisper key by `agent_name` (`codex_mlx_whisper`, `openclaw_mlx_whisper`). `ClaudeCodeProvider`'s keys stay byte-for-byte (existing tests assert bare `claude_cli` + `agent_mlx_whisper`). CLI keys are already distinct (`claude_cli` / `codex_cli` / `openclaw_cli`), so only the mlx-whisper key needs namespacing on the new arms.

Purpose: Completes the agent-native lock — Yulu reuses whichever of the three trusted agents the user already runs, with each agent's configured stack honestly aggregated into one report.
Output: `CodexProvider` + `OpenClawProvider` in `provider.py`, both registered in `default_providers()`, plus `tests/test_multi_agent_providers.py` proving ABC conformance, present/absent provenance, never-raise, no-new-subprocess, and collision-free three-agent aggregation through doctor.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host filesystem / login-shell PATH → provider | `probe_command` resolves a binary via `$SHELL -lc 'command -v X'`; the providers consume the result but add no resolution of their own |
| provider entries → doctor `host_capabilities` report | the three providers' `capabilities()` dicts are merged into one JSON report consumed by the tRPC capabilities router / settings UI |

This phase adds **no new subprocess, exec, or path-resolution surface** — both new providers delegate entirely to Phase-3's `probe_command` / `probe_mlx_whisper` and only relabel provenance (D-05), preserving the Phase-3 invariant T-03-05 (a provider issues no new subprocess of its own). The probed binary names (`codex`, `openclaw`) are fixed Yulu-known tokens, never free-form input (inherits T-03-02 list-form, no `shell=True`).
