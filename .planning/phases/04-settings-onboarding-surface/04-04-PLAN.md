<objective>
Add a skippable first-run onboarding walkthrough (SET-03, D-06, D-07) mounted in the root layout as a dismissable overlay. It reflects LIVE permission/capability status by consuming `trpc.capabilities.host_capabilities` (04-01) — e.g. recording-dir writable, claude/whisper detected, model present — and it is dismissable WITHOUT completing any step (never forced; a forced/unskippable onboarding is an explicit Out-of-Scope anti-feature).

First-run detection uses BOTH a config flag (`config.onboarding_dismissed`, persisted via the existing config router so the dismissal survives across browsers/machines) AND `localStorage` (so it never flashes on a returning user before the config query resolves). Once dismissed via either, it stays gone.

Purpose: this is the SET-03 deliverable and the first-run face of the capability report — it shows the user what Yulu can see on their machine, then gets out of the way.
Output: Onboarding overlay component + root.tsx mount + onboarding.css + Vitest test (Wave 0).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| capabilities/config → Onboarding | the overlay RENDERS server status + a boolean flag; display-only, no command surface |
| Onboarding → config.update | writes a single boolean `onboarding_dismissed`; bounded by the config router's key regex |
| browser localStorage → first-run check | client-side dismissal hint; worst case re-shows a skippable overlay (no security impact) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-FORCE | Repudiation/Usability | onboarding skippability | mitigate | "Skip" dismisses WITHOUT completing any step and persists the flag; a dismissed user never sees it again. Forced onboarding is an explicit Out-of-Scope anti-feature; the no-reappear + skip-without-complete behavior tests enforce SET-03. |
| T-04-FLAG | Tampering | onboarding_dismissed config write | accept | Single boolean via the existing config-update path (key-regex validated, Zod `.passthrough()`); tampering only re-shows a skippable overlay. No elevation, no data risk. |
| T-04-XSS | Tampering | rendering capability detail/status in the overlay | mitigate | Report strings rendered as React text children (auto-escaped); never `dangerouslySetInnerHTML`. |
| T-04-SC | Tampering | npm installs | mitigate | No new packages (existing React/tRPC/Vitest). No legitimacy checkpoint required. |
</threat_model>
