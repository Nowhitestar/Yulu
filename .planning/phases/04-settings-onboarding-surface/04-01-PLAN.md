<objective>
Build the server-side capability surface Phase 4 consumes: a new `capabilities` tRPC router that shells `doctor.py --json` and returns the Phase 3 `host_capabilities` report section (SET-01, D-01), plus a `detected_models` query so the UI model selector has real, selectable whisper models to choose from (SET-04, D-05).

The Phase 3 detection contract is COMPLETE and frozen; this plan extends it additively only. `scan_models` in `capabilities/probes.py` returns an aggregate ("N models, X bytes") in its `detail`, which is insufficient for a pick-list. This plan adds a sibling `list_models()` (new function — `scan_models` is untouched) that returns per-model name/path/size, and exposes it through the router. No existing report field changes shape.

Purpose: the web UI cannot render provenance, configure transcription, or run a model selector until the report and the model list are reachable over tRPC. This plan is the data spine for plans 04-02, 04-03, 04-04 (all Wave 2 consumers).
Output: `capabilities` router registered in `_app.ts`; `list_models()` in `probes.py`; Vitest router test + pytest helper test (Wave 0).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → yulu_ui tRPC | UI calls the new capabilities queries; untrusted client cannot pass commands |
| yulu_ui → subprocess (doctor.py) | the router spawns a child process; only Yulu's own `doctor.py` / `list_models` may be the program |
| config.json → router | the router READS config indirectly via doctor; it must never execute config-supplied command values |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `list_models()` model-root globbing | mitigate | Reuse the fixed `_model_roots()` allowlist; dedupe by `Path.resolve()`; no user-supplied path segment, no `..`. Asserted by the path-bounding behavior test. |
| T-04-EX | Elevation/Tampering | capabilities router subprocess spawn | mitigate | The router spawns ONLY `python3 doctor.py --json` and the `list_models` one-liner — never a value from `config.transcription.cloud_command`/`config.llm.command`. Grep gate + behavior test confirm no user-command exec. doctor's own `llm.command` stays RESOLVED-not-executed (Phase 3 T-03-01 preserved). |
| T-04-DOS | Denial of Service | doctor subprocess hang | mitigate | Spawn has a ~10s timeout + SIGKILL; timeout returns the typed degraded shape so a hung/slow doctor never blocks or blanks the UI. |
| T-04-INFO | Information Disclosure | doctor JSON → browser | accept | Local-first single-user UI on 127.0.0.1; the report contains only local paths/versions the user already owns. No PII, no secrets (Yulu holds no keys). |
| T-04-SC | Tampering | npm/pip installs | mitigate | This plan adds NO new packages (stdlib python + existing tRPC/Zod/Vitest only). No legitimacy checkpoint required. |
</threat_model>
