<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → config.transcription.cloud_command | user supplies their OWN command (trusted-by-user, like llm.command); Yulu stores it verbatim and never executes it in THIS phase |
| user → config.transcription.mode | a constrained enum value persisted to config |
| detected_models query → selector | display-only model list; the chosen value is a path string persisted to config |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-KEY | Information Disclosure | cloud transcription credential surface | mitigate | The cloud path is a COMMAND field (CommandEditor, array-of-strings) with the same trust model as `llm.command` — Yulu holds and asks for NO cloud API keys. Enforced by grep gate (no password/api-key/token/secret input) + the no-key behavior test. This is the HIGH-severity guardrail for Phase 4. |
| T-04-CMD | Tampering/Execution | cloud_command value | accept | The value is the user's own command, stored verbatim; Phase 4 does NOT execute it (only persists). When Phase 5 wires execution it follows the existing llm.command subprocess boundary. No injection surface added here. |
| T-04-MODEL | Tampering | model selector value | mitigate | Options are constrained to `detected_models` (paths from the path-bounded `list_models`, 04-01 T-04-01); the persisted value is one of those discovered paths, not free user text. |
| T-04-SC | Tampering | npm installs | mitigate | No new packages (existing React/tRPC/CommandEditor/Vitest). No legitimacy checkpoint required. |
</threat_model>
