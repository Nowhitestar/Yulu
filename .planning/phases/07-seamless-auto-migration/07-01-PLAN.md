<interfaces>
Contracts this plan binds to (already in the codebase — do NOT re-implement):

- `release_installer.read_install_metadata(runtime_dir: Path) -> dict` — returns the parsed `.yulu-install.json` (or `{}` if missing/corrupt). The doc carries `schema` (installer, ==1) and, on a Phase-6-touched install, `schema_version` (==2) + `steps`. A v0.5.x install has NEITHER `schema_version` NOR `steps`.
- `release_installer.install_metadata_path(runtime_dir) -> runtime_dir / ".yulu-install.json"`.
- `provision/state.py` exposes `SCHEMA_VERSION = 2` (the current ledger schema). Import it as the "current" target rather than hardcoding `2` in two modules.
- `provision/state.py` `_INSTALLER_KEYS` enumerates the installer-written keys that must survive any rewrite (`source`, `version`, `sha256`, `installed_at`, ...). Detection must treat a missing `schema_version` as "needs migration", NOT as "corrupt".
- `MacOSPathResolver().data_dir()` resolves the recording root (env -> `config.json` `audio.output_dir` -> `~/Movies/Yulu`). The PLAN does not call it; it records, as a PlanStep, that apply must route the legacy hardcoded default through this resolver.
- Config to correct lives at `runtime_dir()/config.json` (`~/.config/yulu/config.json`), the dead field is at `transcription.mlx.python` (see config.example.json line 34-37). This is SEPARATE from the runtime tree at `~/.yulu`.

Contract this plan DEFINES (consumed by Plan 03):

- `MigrationNeed` — frozen dataclass: `needs_migration: bool`, `from_schema: int | None` (None == v0.5.x / absent), `to_schema: int` (== state.SCHEMA_VERSION), `reasons: list[str]` (human-readable: "schema_version absent", "old layout", ...).
- `MigrationPlan` — frozen dataclass: `steps: list[PlanStep]`, `need: MigrationNeed`. A `render()` (or `__str__`) prints the dry-run summary.
- `PlanStep` — frozen dataclass: `name: str`, `description: str`, `kind: str` (one of `"config_correction"` | `"path_route"` | `"schema_stamp"`). NO side effects — a PlanStep is a description, never an action.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| existing-install state -> migration detector | The on-disk `.yulu-install.json` and `config.json` are untrusted input (could be corrupt, partially written, or hand-edited). Detection must never crash or mutate on a malformed file. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | detect.py reading `.yulu-install.json` | mitigate | Read via `release_installer.read_install_metadata` which degrades corrupt JSON -> `{}`; detect then treats absent schema as "needs migration" (safe default) — never crash, never trust a tampered schema as "current". |
| T-07-02 | Denial of Service | plan.py / detect.py on a hand-edited huge config | accept | Files are user-local, single-user, bounded by the install; reads are one-shot `read_text` with no recursion. No untrusted network input. Low-value local target. |
| T-07-03 | Information Disclosure | error paths leaking a bad path into output | mitigate | Detection degrades silently (no raise); reasons are fixed human strings, never an interpolated raw file path from a parse failure. |
| T-07-DI | Tampering (data-integrity) | the whole migration | mitigate (scope: this plan is read-only) | detect/plan perform ZERO mutation — the data-integrity guarantee (backup->apply->verify->prune, recording-guard) lives in Plans 02/03. This plan's contribution is that the destructive apply runs only against an already-proven, dry-run-rendered plan. |
