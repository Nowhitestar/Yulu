## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-13 | Information Disclosure | Global process tap captures ALL system audio | mitigate | The tap is the user's explicit, TCC-gated recording action; `desc.muteBehavior = .unmuted` keeps it passthrough (no silent interception); audio stays local (PROJECT.md core value). The first-run NSAudioCaptureUsageDescription prompt makes the system-wide scope explicit to the user (02-RESEARCH.md:572). |
| T-02-14 | Denial of Service | Aggregate device left registered after a crash (leaks a virtual device) | mitigate | `kAudioAggregateDeviceIsPrivateKey: true` keeps it out of the system device list; `teardown()` destroys tap + aggregate; `applicationWillTerminate` calls `audioCapture?.stopCapture()` so a clean exit tears down (02-RESEARCH.md:575). |
| T-02-15 | Spoofing/Elevation | Direct-launch TCC re-attribution on 14.4+ (new audio-only scope under launchd parent) | mitigate | Binary stays inside the correctly-signed `.app` (stable bundle id). The Assumption-A1 risk is VALIDATED on a clean machine in Task 3 (the blocking human-verify), not assumed - a failure is a blocking finding. |
| T-02-16 | Tampering | Missing NSAudioCaptureUsageDescription / entitlement -> daemon killed on first tap | mitigate | Task 2 adds NSAudioCaptureUsageDescription and keeps the mic entitlement (Pitfall 4 / A2); Task 3 confirms the prompt actually appears on a clean 14.4+ machine. |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | N/A - macOS system frameworks only (CoreAudio/AudioToolbox added via `-framework`, no package install); the tap reference code is hand-ported from insidegui/AudioCap as a pattern, not a dependency (02-RESEARCH.md:93-97). No legitimacy checkpoint required. |
