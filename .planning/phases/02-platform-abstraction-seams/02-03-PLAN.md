| config.json → status_agent / daemon | User-editable path strings read to locate recordings |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | Spoofing/Elevation | Direct-launched daemon's TCC attribution (responsible process changes from `open`/LaunchServices to launchd) | mitigate | The binary stays inside a correctly-signed `.app` with a stable `CFBundleIdentifier` (com.yulu.audiodaemon), so bundle identity is preserved (02-RESEARCH.md:238-243). The residual re-attribution risk (Assumption A1) is verified on a clean machine in 02-04's blocking human-verify checkpoint — NOT assumed away here. |
| T-02-10 | Information Disclosure | CaptureBackend / SCK arm capturing system audio | accept | The SCK capture is the user's explicit, TCC-gated recording action; audio stays local (PROJECT.md core value). No new disclosure surface — this plan only refactors the existing capture behind a protocol. |
| T-02-11 | Tampering | status_agent reading config.json `output_dir` (path traversal) | accept | Severity low: resolves only to a directory the same single user owns; the menu-bar list reads filenames, executes nothing. Same disposition as T-02-02 (PathResolver). |
| T-02-12 | Tampering | Socket control channel to the daemon | accept | Unchanged this phase: socket is `chmod 0o600` + per-fd timeouts + bounded request size (audio_daemon.swift:607/630) — the protocol refactor does not alter the socket surface (02-RESEARCH.md:574). |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | N/A — Swift system frameworks only (ScreenCaptureKit/CoreAudio already linked); no package manager touches this plan (02-RESEARCH.md:93-97). No legitimacy checkpoint required. |
