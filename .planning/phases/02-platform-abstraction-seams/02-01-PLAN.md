<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config.json → PathResolver | User-editable JSON file read to resolve directories; untrusted path strings cross here |
| ServiceSpec → launchctl | Daemon spec (fixed, from Yulu config) rendered to a plist and handed to the launchd subprocess |
| launchctl/subprocess argv | Process-control commands executed by MacOSDaemonManager |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering/Elevation | MacOSDaemonManager launchctl calls | mitigate | All subprocess calls use list form `subprocess.run([...], check=False)` — never `shell=True`, never f-string interpolation of a value into a command string (02-RESEARCH.md:571). Acceptance criterion greps for `shell=True` absence. |
| T-02-02 | Tampering | PathResolver resolving config-driven `audio.output_dir` (path traversal / symlink escape) | accept | Severity low: the resolved dir is the user's own recording location on their single-user machine; a traversal resolves only to paths the same user already owns. No privilege boundary crossed. Documented; revisit in Phase 5 (DATA-03 cloud-root detection) where folder-picker input gets validated. |
| T-02-03 | Information Disclosure | PathResolver / DaemonManager error messages | mitigate | Fallback paths return defaults silently (no raise leaking the bad path); status() returns neutral strings only, never raw launchctl output that could echo environment/paths (ASVS V7). |
| T-02-04 | Spoofing | launchd job name collision (ServiceSpec.name → Label) | accept | Severity low: names come from fixed Yulu config (`com.yulu.*`), not external input; LaunchAgents is per-user `~/Library/LaunchAgents`. No untrusted producer of spec.name in this phase. |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | N/A this plan — stdlib-only Python, zero package installs (02-RESEARCH.md:93-97 Package Legitimacy Audit: nothing to install). No `[ASSUMED]`/`[SUS]` packages → no legitimacy checkpoint required. |
</threat_model>
