<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> `yulu provision <step>` | Step name is untrusted input; must resolve to a FIXED named step only (no arbitrary script path) |
| registry -> bash setup_*.sh | The registry spawns a fixed, in-repo script per step; the only variable passed is the mode literal |

## STRIDE Threat Register (ASVS L1 + V10 supply-chain)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Elevation/Injection | ScriptStep.apply subprocess | mitigate | subprocess.run uses an argv LIST (no shell=True); the script path is a fixed REGISTRY entry joined under SCRIPTS_DIR, never caller-supplied; only the mode literal is variable (V5 input validation) |
| T-06-02 | Tampering | step name dispatch | mitigate | step_by_name resolves against the fixed REGISTRY table; an unknown name raises rather than executing anything (no arbitrary-step execution) |
| T-06-03 | Tampering | check() probe side effects | mitigate | check() is contractually read-only (probe, no mutation) so a partially-applied step's re-run reasoning stays sound — enforced by the apply()=skipped-when-check()-true test |
| T-06-04 | DoS | wrapped bash hangs | accept | the six scripts are non-interactive and already hermetically tested (test_setup_decomposition.py); a per-step subprocess timeout is a possible hardening but not load-bearing this plan (no untrusted network in a step body) |
</threat_model>
