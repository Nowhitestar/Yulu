<objective>
Create `provision/state.py`: the resumable per-step ledger backing `.yulu-install.json`. It mirrors `queue_store.py`'s proven durability primitive (`tempfile.mkstemp` + `os.replace` atomic write, optional `fcntl` lock) and implements the kill-at-step-N resume contract — mark a step `running` durably BEFORE `apply()`, `ok` only AFTER a clean exit, so a SIGKILL leaves the step non-`ok` and resume re-runs exactly it (and only steps after it). Crucially it EXTENDS the existing installer-written `.yulu-install.json` (preserving `source`/`version`/`sha256`) rather than treating it as a greenfield file.

Purpose: PROV-04 requires provisioning to be resumable via the per-step `.yulu-install.json`; PROV-02's spike exit criterion (1) is kill-at-step-N resume. Per D-04 the ledger is a `{step:{status,ts}}` map + `schema_version` built on the existing `source` field. RESEARCH Pitfall 3 is the headline trap: clobbering `source` flips a release install into the swiftc dev branch via `lib/common.sh:detect_source`.
Output: `provision/state.py` plus Wave-0 tests `tests/test_provision_state.py` and `tests/test_provision_resume.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provisioning run -> `.yulu-install.json` | A crash/SIGKILL mid-write must never leave a corrupt or partial ledger that misdrives resume |
| installer-written doc -> ledger extension | The Phase-1 `source` field is security-relevant (drives dev-vs-release script forks); dropping it is a tamper-equivalent regression |

## STRIDE Threat Register (ASVS L1 + V12 Files & Resources)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05 | Tampering/DoS | ledger write | mitigate | tempfile.mkstemp + os.replace atomic write (POSIX-atomic) so a kill mid-write leaves either the old or the new doc, never a torn file — mirrors queue_store.py; corrupt-on-read degrades to {} (fresh), never crashes (V12) |
| T-06-06 | Tampering | resume after kill | mitigate | mark(running) BEFORE apply / mark(ok) only AFTER: a killed step is never ok, so resume re-runs exactly it; an ok step is never re-run — the kill-at-step-N test encodes this (prevents both skip-needed-step and redo-destructive-work) |
| T-06-07 | Tampering | installer source clobber | mitigate | mark() preserves source/version/sha256 via setdefault/merge (Pitfall 3): a dropped `source` flips lib/common.sh:detect_source into the swiftc dev branch on the next update — the PRESERVE test is the guard |
| T-06-08 | DoS | concurrent provision writers | accept | provisioning is single-writer (one run at a time); os.replace is atomic regardless; optional fcntl.flock parity with queue_store is cheap insurance, not load-bearing |
</threat_model>
