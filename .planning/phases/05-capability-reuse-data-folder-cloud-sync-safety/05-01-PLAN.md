<objective>
Land the DATA-02 physical split between machine-local runtime/state and configurable content, with the runtime LOCK enforced — and route the three hardcoded content-root literals through `data_dir()` so new content follows the configurable folder. This is the HARD PREREQUISITE (D-01, D-06): it ships in Wave 1, BEFORE Plan 04 wires the cloud-capable folder picker, so a user can never put SQLite/sockets/locks in a synced folder.

Purpose: Runtime/state (SQLite DBs + WAL, Unix sockets, locks, PIDs, .state.json) must be machine-local and never syncable; SQLite-on-cloud-sync corrupts (WAL checkpoint + hot-journal relocation, documented). Content (recordings/transcripts/summaries/voicemails) is the only thing the picker moves.
Output: A diverged `runtime_dir()` (locked, never reads config) + `assert_runtime_not_synced()` startup guard; three content literals routed through `data_dir()`; Wave-0 tests for the lock and the routing.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config.json `audio.output_dir` → PathResolver.data_dir() | User-controlled content-root value crosses into path resolution |
| runtime_dir() → filesystem (SQLite/sockets/locks) | Machine-local-only; a synced path here is the safety failure DATA-02 prevents |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering / EoP | A crafted `audio.output_dir` (`../../etc`) read into data_dir() | mitigate | data_dir() already `expanduser()`s + handles a leading `~/`; routing the three literals through it (not new shell interpolation) inherits that bounding. No path is ever shell-interpolated (ASVS V5). |
| T-05-02 | Tampering | Runtime dir routed under a synced root → SQLite WAL corruption / eviction | mitigate | `assert_runtime_not_synced()` (Task 1) rejects a cloud-detected runtime dir at startup; runtime_dir() never reads user config, so the only vector is $YULU_CONFIG_DIR (dev-only) — the guard catches it. |
| T-05-03 | Info disclosure | data_dir() resolution leaking a bad path on error | mitigate | The resolver's `_config_output_dir` degrades silently to the default on any parse/IO failure (existing T-02-03 behavior, preserved); the guarded helper falls back to the historical literal, never surfacing a raw bad value. |
| T-05-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan (stdlib-only Python); slopcheck N/A per RESEARCH Package Legitimacy Audit. |
