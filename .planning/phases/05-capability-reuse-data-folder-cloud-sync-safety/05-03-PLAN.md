<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI folder path -> cloud.detect tRPC -> python | A user-chosen path string crosses into a subprocess argv |
| filesystem -> is_cloud_root/os.stat | Reads metadata (st_flags) of an arbitrary user path; must not materialize cloud files or follow symlinks out of bounds |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-07 | Tampering / Command injection | The user path reaching python via the tRPC route | mitigate | The path is passed as a SEPARATE spawn argv element and read via sys.argv inside the python program — never concatenated into a `-c` string or a shell command (Security V5; mirrors capabilities.ts list-form spawn). zod validates a non-empty string at the boundary. |
| T-05-08 | DoS (bandwidth) / Info disclosure | Detection triggering a network download of a dataless file | mitigate | `os.stat` is metadata-only and does NOT materialize a dataless file (verified on-device — the flag reads without download); detection NEVER `open()`s/reads file contents, stat only. |
| T-05-09 | Tampering (symlink escape) | The child scan following a symlink out of the CloudStorage root | mitigate | The bounded `[:64]` child scan uses `os.stat(child, follow_symlinks=False)` (RESEARCH Pattern 1) so a symlinked entry cannot redirect the stat outside the resolved path. |
| T-05-10 | DoS | A pathological directory with huge fan-out stalling detection | mitigate | The child scan is hard-bounded to the first 64 entries; `is_cloud_root` resolves once and never recurses; the tRPC route caps the python subprocess with a SIGKILL timeout (capabilities.ts pattern). |
| T-05-SC | Tampering | npm/pip/cargo installs | mitigate | No new package (stdlib python + existing TS deps); slopcheck N/A per RESEARCH Package Legitimacy Audit; no [ASSUMED]/[SUS] package -> no blocking-human checkpoint required. |
</threat_model>
