<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `curl \| bash` install.sh → user machine | The entry script decides which prerequisites to enforce; mis-gating could either block release users or let a dev install proceed without swiftc. |
| Orchestrator → concern scripts | The orchestrator passes resolved decisions; an unvalidated mode could run the wrong fork. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-12 | Tampering | install.sh prerequisite gating | mitigate | The Xcode pre-flight is gated on `--dev` using the same proven conditional idiom as the existing git check; release installs rely on notarized+stapled+attested binaries (plans 03/06), not on a local compiler. The `curl\|bash` SIGNATURE gate (CONCERNS §2b) is explicitly Phase 6 and is NOT regressed here. |
| T-01-13 | Spoofing | install-mode resolution | mitigate | `resolve_install_mode` reads the `.yulu-install.json` source field written by release_installer.py and accepts only a local `--dev` override; no remote input selects the mode. Defaults safely (a missing file in a non-dev context defaults to release prebuilt path). |
| T-01-14 | Denial of Service | hermetic test harness running real brew/launchctl | mitigate | The decomposition tests run concern scripts behind a no-op PATH shim in tmp HOME/CONFIG_DIR — no host mutation, no network — so CI cannot brick the runner or hang on a prompt (scripts are non-interactive standalone per Pitfall 5). |
| T-01-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan. Tests use stdlib `subprocess`/`pathlib`. No `[ASSUMED]`/`[SUS]` package introduced. |
</threat_model>
