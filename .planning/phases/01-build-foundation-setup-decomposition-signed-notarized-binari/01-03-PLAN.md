<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Build script → Apple code-signing identity | `build_*.sh` invokes `codesign` with whatever identity `YULU_CODESIGN_IDENTITY` / the keychain provides; a wrong/over-broad entitlement set widens the bundle's runtime privileges. |
| Signed bundle → macOS TCC/Gatekeeper | The entitlements declare what the hardened-runtime bundle may access; over-broad = larger attack surface, missing = silent TCC failure. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Elevation of Privilege | over-broad entitlements | mitigate | Least-privilege: Yulu.app gets ONLY `audio-input`; StatusAgent gets ONLY `apple-events`; explicitly NO screen-capture entitlement (SCK is TCC-only). test_entitlements_present.py asserts the absence of extra keys. (RESEARCH Security Domain V1.) |
| T-01-07 | Tampering | dropping `--deep` / adding hardened runtime | mitigate | Bottom-up signing (inner Mach-O then bundle) with `--options runtime` + secure `--timestamp` replaces the `--deep`/`--timestamp=none` smell; `codesign --verify --strict` proves the signature. This is the prerequisite for Apple notarization (malware scan) in plan 06. |
| T-01-08 | Information Disclosure | signing cert / Team ID in a committed script | mitigate | No credential value is written to any script — only the `YULU_CODESIGN_IDENTITY` env var name. Acceptance criteria greps for hardcoded cert/Team ID/`.p12`/`.p8` and must find none. (D-08, RESEARCH Security V14.) |
| T-01-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs. First-party Apple `codesign` only; the entitlement test uses stdlib `plistlib`. No `[ASSUMED]`/`[SUS]` package introduced. |
</threat_model>
