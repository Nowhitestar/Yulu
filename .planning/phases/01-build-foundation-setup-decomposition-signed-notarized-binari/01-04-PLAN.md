<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Release install path → shipped binaries | The release fork trusts the pre-built signed+stapled binaries in the zip; integrity is established by notarization (plan 06) + attestation (plan 06) + the existing SHA-256 check. |
| Installer → macOS TCC | The TCC reset re-prompts Microphone/ScreenCapture after the signing-identity change. |
| Daemon interpreter resolution | The plist `__PYTHON__` token selects which python3 runs the daemon; a wrong interpreter could import unexpected code. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-09 | Tampering | release path trusting binaries without quarantine strip | mitigate | Removing the `xattr` strip is SAFE precisely because the release binaries are notarized + stapled (plan 06) and SHA-256-verified by release_installer.py; the strip was a smell that masked unsigned binaries. Gatekeeper now does the integrity check. |
| T-01-10 | Spoofing | wrong python3 interpreter for the daemon | accept | Phase 1 points `__PYTHON__` at the system python3 (D-01); full interpreter-ambiguity resolution + provenance is Phase 3 (DETECT-04). The plist path is operator-controlled, not remote-influenced. Low residual risk this phase. |
| T-01-11 | Information Disclosure | TCC reset over-prompting | accept | `tccutil reset` only resets Yulu's own bundle ID grants and re-prompts the user — it cannot grant access silently; one extra consent click after the identity change is the expected, documented cost. |
| T-01-SC | Tampering | npm/pip/cargo installs | mitigate | setup_capabilities.sh VERIFIES mlx-whisper importability but does NOT pip-install anything this phase (D-05 defers install to Phase 5); no package install path is added. No `[ASSUMED]`/`[SUS]` package introduced. |
</threat_model>
