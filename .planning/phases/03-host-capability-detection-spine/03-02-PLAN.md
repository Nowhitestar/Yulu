## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Tampering | ClaudeCodeProvider probing `claude` | mitigate | The provider does not resolve or execute commands itself — it delegates to Plan 01's `probe_command` (list-form `$SHELL -lc 'command -v claude'`, then a bounded `--version` read), inheriting T-03-01/T-03-02 mitigations. The provider only RELABELS provenance; it adds no new execution surface. |
| T-03-06 | Spoofing | provider registration (`default_providers`) | accept | Severity low: the provider list is a fixed in-code constant (`[ClaudeCodeProvider()]`); no untrusted producer registers a provider in this phase. Phase 8 adds Codex/OpenClaw as code, not runtime-loaded plugins. |
| T-03-04 | Information Disclosure | provider-contributed `detail` strings | mitigate | Capabilities carry only the short `detail` from Plan 01's probes (version or "not on login PATH"); the provider never raises and never surfaces full environment/paths (inherits the doctor "never raises" contract). |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | N/A this plan — stdlib-only Python (`abc` + the Plan-01 report/probes imports), zero package installs. No `[ASSUMED]`/`[SUS]` packages → no Package Legitimacy checkpoint required. |
