<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| raw bootstrap → GitHub Release asset | Network-delivered executable code crosses into the local installer; stable code must be immutable and release-owned. |
| user target argument → release URL/argv | A version string influences a URL and child argv; malformed input must not become shell syntax. |
| installed/verified staged runtime → installer guard | The installer imports code only from a current installed runtime or a checksum/signature/manifest-verified staged runtime. |
| audio-daemon socket state → runtime mutation | Live recording state decides whether rename, git update, setup, or daemon lifecycle work is permitted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01-01 | Tampering / supply-chain version mix | `install.sh` + `package.sh` | mitigate | Stable raw bootstrap downloads a Release-owned `install.sh`; packaging injects exact helper plus exact validated tag atomically; packaged default/latest is converted to that tag. Existing checksums, signatures, signed runtime manifest, remote-byte comparison, and rollback remain intact. |
| T-09-01-02 | Tampering / shell injection | `--version` URL and forwarded argv | mitigate | Normalize and validate SemVer before URL construction, use fixed repository/asset names and quoted arrays, and add an adversarial metacharacter test. No `eval`, string-built command, or `shell=True`. |
| T-09-01-03 | Denial of Service / data loss | release/dev update during active WAV capture | mitigate (HIGH, blocking) | Reuse `migrate.guard.recording_active` under the install lock and at mutation/setup boundaries; active status raises a typed refusal before stop/setup. Tests assert zero mutation and zero service repair while active. |
| T-09-01-04 | Tampering / fail-open update | missing or unloadable trusted guard | mitigate (HIGH, blocking) | Existing dev update fails closed. Legacy release update may do read-only fetch/verification only, then must use the verified staged guard before swap. A module-load failure never means idle; only the canonical guard's established absent-socket contract does. |
| T-09-01-SC | Tampering | GitHub release assets | mitigate | No package-manager install is added. Preserve existing fixed asset names, SHA-256, Developer ID/notarization, signed manifest, attestation, and draft-asset byte comparison; no new dependency legitimacy checkpoint is required. |
</threat_model>
