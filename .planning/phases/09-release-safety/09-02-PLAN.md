<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build scripts/toolchain → Mach-O load commands | Host Xcode defaults are untrusted for the product floor; the target must be explicit. |
| validator argv → native `xcrun vtool` | File paths cross a shell boundary and must remain quoted argv, never evaluated text. |
| extracted release runtime → attestation/upload | The exact bytes users receive must pass the gate before provenance or publication. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-02-01 | Denial of Service | shipped Mach-O with host-default `minos` | mitigate (HIGH, blocking) | Explicit `arm64-apple-macosx13.0` on every compile plus exact `vtool` check on all five extracted release binaries; any mismatch blocks the job. |
| T-09-02-02 | Tampering | incomplete or source-only compatibility gate | mitigate | Fixed five-path inventory is asserted in tests and executed on the exact verified runtime before attestation/upload; `.ci-build` is only the early feedback gate. |
| T-09-02-03 | Tampering / shell injection | checker binary paths | mitigate | Iterate quoted `"$@"`, call fixed `xcrun vtool` argv, use no `eval`/glob/string command, and test a metacharacter path with a marker that must remain absent. |
| T-09-02-04 | Tampering / fail-open release | missing `vtool`, missing path, unparsable output, wrong platform/arch | mitigate (HIGH, blocking) | `set -euo pipefail`, explicit input checks, non-zero native-tool handling, required `platform MACOS` and exact `minos 13.0`; workflow ordering leaves release draft/unpublished on failure. |
| T-09-02-SC | Tampering | build/release tooling | mitigate | No new package or action. Reuse Apple `swiftc`/`xcrun vtool`, existing Actions, signing, notarization, checksum, manifest, and attestation controls. |
</threat_model>
