# Yulu v0.23.0-rc.18

RC18 repairs Application Migration from a normal user-owned `LaunchAgents`
directory. It retains RC17's legacy caption virtualenv and early-retry repairs,
RC16's containing-App capture permission declarations, and RC15's database
initialization repair.

- **Shared source directory** — a user-owned `~/Library/LaunchAgents` with `0755`
  or `0750` permissions is no longer mistaken for Yulu-private state requiring
  `0700`. Migration preserves that directory's mode and unrelated services.
- **Safe migration and rollback** — allowlisted Yulu service plists retain their
  original modes through archival and rollback. Yulu's journal and rollback
  directories remain private. Foreign owners, symlinks, group/world-writable
  sources, and replaced directory identities remain blocked.
- **Consistent checks** — discovery, service snapshots, transaction ownership,
  and pre-mutation revalidation use the same LaunchAgents authority rules.
  Group/world-writable Yulu plists are rejected before they can authorize a
  migration or service restart.

If RC17 reports `unsafe private migration directory owner or mode`, replace the
complete signed App with this candidate and use its explicit migration Retry.
Do not chmod the shared LaunchAgents directory, delete a journal, edit databases,
or patch the signed App to work around the error. The failed preflight leaves
legacy data and services in place.

The failure was reproduced in the signed RC17 App on the existing physical
Apple Silicon Mac and in regression fixtures. The repaired source passes the
migration regression suite and a read-only check of the actual source directory
and allowlisted plist metadata. These checks are not installed migration or
release acceptance. Earlier candidates and their evidence remain preserved.

OAuth custody, selected transcription and summary providers, data disclosures,
and manual Sharing are unchanged. Recording Processing stops after transcript
and summary commit and never shares automatically.

Verify this signed App on the physical host first. Reuse an existing isolated
environment only for the final clean-install or real v0.22.2 upgrade evidence;
this repair does not require another VM. Formal acceptance targets macOS 14+
arm64; macOS 13 remains a deployment target, not an acceptance environment.
Stable v0.23.0 remains blocked until #170 accepts this exact RC18 source and
#171's separate publication and update checks pass.
