# Yulu v0.23.0-rc.15

RC15 fixes a fresh-install database initialization failure found on the public
RC14 App. It continues the self-contained drag-to-Applications candidate line.

- **First recording detail** — the Host prepares missing prompt, vocabulary and
  search databases before reporting ready, using the schemas, seeds and Python
  bundled in the signed Application Runtime. Opening the first recording no
  longer depends on running a setup script or installing development tools.
- **Existing data stays intact** — preparation validates private staging and
  publishes without overwriting an existing database. User-edited templates and
  migrated data are preserved; failed initialization cleans staging and allows
  a normal retry without claiming readiness.
- **Regression and package gates** — source tests exercise a real fresh Host,
  first-recording HTTP requests, restart persistence, failure/retry and concurrent
  database preservation. Runtime inventory checks require the bundled initializer.

Grok CLI-compatible OAuth, explicit provider/model selection and data-path
disclosures are unchanged. Recording Processing ends with transcription and
summary; manual Sharing still requires a fresh confirmation. Conversation and
Calendar remain optional capabilities.

RC14 assets, tags and partial acceptance evidence remain preserved. The separate
silent-audio observation from that validation is not claimed fixed by this
database repair. This prerelease still requires real fresh-install and v0.22.2
upgrade evidence, including recording, summary, sharing and lifecycle checks;
green source tests are not installed-product acceptance.

The collector and candidate must come from the same clean source. macOS 13
remains the deployment target, not a formal acceptance environment; required
journeys run on macOS 14+ arm64. Stable v0.23.0 remains gated on #170 accepting
this exact RC15 source and the separate publication/update checks in #171.
