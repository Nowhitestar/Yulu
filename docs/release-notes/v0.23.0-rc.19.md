# Yulu v0.23.0-rc.19

RC19 repairs a real Application Migration race found after installing the signed
RC18 App on the existing physical Mac. macOS can acknowledge a service bootout
before removing the service. An immediate state check incorrectly began rollback,
which could mistake the still-removing Host for an already-restored service.

- **Wait for actual state** — migration waits with a bounded timeout for launchd
  removal and restoration. Unknown or unauthorized observations remain blocked.
- **Recover pending work safely** — an outstanding bootout is journaled before
  the command and must settle before rollback decides whether to restart a job.
  Recording initiators still stop before the final native Capture idle guard;
  Capture is stopped last, never to interrupt an active recording.
- **Recover a blocked rollback** — reopening the complete updated App resumes
  the existing transaction's rollback checks. A new recording blocks recovery;
  registered bundled services must be proven unregistered before legacy services
  can be restored. Original plist bytes, ownership and modes remain validated.
- **Retry an early failure** — a rollback that failed before archival now leaves
  a verified empty, transaction-bound archive and preserves attempt lineage for
  the existing explicit Retry action. No journal reset or data edits are needed.
- **Verify normal disk names** — the independent package verifier also supports
  the ordinary `/Volumes/Yulu 1` mount created when an earlier disk is open.

RC18's normal LaunchAgents directory permissions, RC17's retired virtualenv and
early-retry repairs, and the prior capture-permission and database-initialization
fixes remain included. Existing recordings, configuration, OAuth custody, and
selected transcription/summary providers are preserved. Recording Processing
ends after transcript and summary commit; sharing remains exclusively manual.

The asynchronous failure is covered by isolated regression fixtures, including
timeout, rollback, changed-plist rejection, and an active-recording guard. Passing
source checks and publishing an App are not installed acceptance. Replace the
whole signed App; do not patch its contents, edit the transaction journal, change
the shared LaunchAgents permissions, or reprocess historical meetings to test it.

Use the physical Mac first. Reuse an existing isolated environment only where
final clean-install or real v0.22.2 upgrade evidence requires it; do not create a
VM for this candidate. Formal acceptance is macOS 14+ arm64. macOS 13 remains a
deployment target but is not an acceptance environment. Stable v0.23.0 remains
blocked until #170 accepts this exact RC19 source and #171's separate checks pass.
