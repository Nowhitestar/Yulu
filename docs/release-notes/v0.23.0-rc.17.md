# Yulu v0.23.0-rc.17

RC17 repairs Application Migration from a legacy installation that has a local
caption Python virtualenv. It retains RC16's containing-App capture permission
declarations and RC15's fresh database initialization repair.

- **Legacy runtime boundary** — migration leaves the interpreter-bound
  `local-caption/venv` untouched in the legacy rollback source. Other local
  caption data and an existing Runtime Pack still migrate; the App never imports
  the old virtualenv as its active runtime. Models and recordings are preserved.
- **Consistent migration checks** — the Python transaction manifest and Host
  data-preparation leaf use the same exact exclusion. Arbitrary symlinks outside
  that retired subtree and unsafe destination authorities remain rejected.
- **Actionable rollback** — a failed live migration returns its bounded cause
  after restoring legacy ownership. The App reports a rollback with that cause
  instead of labelling every failure as a user cancellation.
- **Retry after early failure** — an explicit retry also handles a verified
  preflight-only rollback that never reached service snapshots or data changes.
  It preserves attempt lineage without requiring fabricated rollback evidence;
  inconsistent mutation metadata still blocks the retry.

If local transcription previously used only the retired virtualenv, install the
verified optional Runtime Pack from Transcription settings before using local
transcription. xAI remains an explicitly selected alternative, never an automatic
fallback. OAuth custody, provider/model selection, data disclosures, and manually
confirmed Sharing remain unchanged. Recording Processing still ends after
transcription and summary; it never shares automatically.

The failure was reproduced on an existing physical Apple Silicon Mac and in
focused fixtures. The corrected source also passes read-only preflight against
that legacy data, but these checks do not establish successful installed
migration, captured audio signal, transcription, summary, or Sharing. Earlier
candidate artifacts and failed evidence remain preserved.

Verify the corrected signed App on the physical host first. Reuse isolated
environments only where final clean-install or real v0.22.2 upgrade evidence
requires them; this repair does not require another VM. Formal acceptance still
targets macOS 14+ arm64, while macOS 13 remains the deployment target. Stable
v0.23.0 remains gated on #170 accepting this exact RC17 source and #171's separate
publication/update checks.
