# Yulu v0.26.0

This release brings the recent voice-input improvements into the stable channel:
clearer dictation, less waiting after speaking, simpler shortcuts, and a smaller
recording panel.

- **Automatic cleanup:** choose light, medium, or heavy editing independently of
  formal, casual, or very casual punctuation. Heavy editing uses natural
  paragraphs and numbered lists for distinct questions or requests, while
  preserving the speaker's meaning and uncertainty. Cleanup can be switched off;
  both the original transcript and edited result remain available in history.
- **Faster text preparation:** xAI dictation can prepare completed paragraphs
  while recording continues and reuse them only when the final transcript and
  editing settings still match. The stop path can finish as soon as the spoken
  tail is finalized. Settings offer a separate fast, non-reasoning cleanup model
  without changing the conversation model. Python bytecode is prepared before
  signing to reduce startup work.
- **Cleaner recognition and captions:** dictation sends only microphone audio
  and no longer injects the full glossary into speech recognition. Text cleanup
  applies only glossary entries matched in the transcript. Silent audio
  intervals are checked before accepting recognition output. Live captions
  display the current utterance, suppress hesitation-only fragments and acoustic
  echoes, and retain meaningful corrections to numbers and negations. The
  duplicate in-app realtime transcript panel has been removed.
- **Shortcuts:** the defaults are `Fn` for dictation, `Fn+Shift` for translation,
  and `Fn+Space` for voice questions. Single modifier keys and left/right
  Command, Shift, Option, and Control are supported. Settings can restore the
  defaults and reject conflicting shortcuts. Existing custom shortcuts remain.
- **Automatic insertion:** focus restoration and insertion checks work better
  with destination editors. Verified insertion dismisses the voice panel without
  a Copy Text prompt. Unconfirmed delivery gets a brief notice; a known failure
  retains the text for recovery without blindly pasting twice.
- **Recording UI:** a half-size capsule uses a blue waveform, aligned finish
  and cancel controls, and smooth entry/exit motion. Routine processing labels
  no longer crowd the capsule; exceptions use a separate notice. The live-caption
  toolbar has an audio-responsive waveform and quieter unfocused presentation.
- **Simpler settings:** dictation and translation use built-in rules instead of
  requiring Prompt Library templates. Translation keeps its target-language
  setting and preserves recognized text if translation fails. Onboarding and
  Voice Input settings explain macOS permissions, distinguish authorization
  from active system-audio capture, and report notification permission for the
  current Yulu App rather than the legacy Status Agent.

## Updating

Use Yulu's update check, or download `yulu-macos-arm64-v0.26.0.dmg` and drag
`Yulu.app` into `/Applications` after recording has finished. Configuration,
recordings, history, and provider credentials remain outside the App.

Automatic insertion and modifier shortcuts require input-control permission for
**Yulu** itself. On macOS 27, look under Device Control and Data Access. System
audio may be listed under System Audio Recording Only. Notifications must also
be enabled for **Yulu**; a grant for the legacy Yulu Status Agent does not
transfer automatically. The update does not change macOS permission switches.

## Verification scope

Coverage includes cleanup preferences and original-text recovery, incremental
reuse and cancellation, microphone-only streaming, silent audio and caption
revisions, modifier shortcuts, native panel motion and insertion outcomes, and
permission-state reporting. The release workflow runs Python and TypeScript
checks, native compilation, signing, notarization, complete runtime inventory,
public asset checksums, and signed update-feed verification.

The accumulated local builds were exercised on a physical Mac. These checks do
not establish identical latency or insertion behavior in every destination app,
nor a new full fresh-install and cross-version migration matrix. Local
transcription remains on-device; cloud editing uses the explicitly selected and
authorized xAI connection. macOS 13 remains the deployment target.
