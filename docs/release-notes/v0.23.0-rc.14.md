# Yulu v0.23.0-rc.14

This candidate supersedes RC13 after real installed Onboarding exposed two
usability blockers. RC13 reached the first installed Onboarding screen, but
that partial progress did not complete Core Activation or product acceptance.

- **readable connection controls** — Settings adapts to the native default
  window and smaller layouts without squeezing capability cards or clipping
  authentication controls. Category navigation and saved wide-window pane
  widths remain available.
- **OAuth browser handoff** — the native App opens asynchronous OAuth links
  and manual authorization links in the system browser. Opening is restricted
  to the App's exact local Host origin and credential-free HTTPS destinations;
  the local product UI remains open. Finish the provider's authorization, return
  to Yulu, and explicitly test each selected capability.
- **regression gates** — CI exercises the rendered Settings layout and a real
  native WebView with synthetic URLs. These development tests do not log in,
  open a real provider session, or claim installed-product acceptance.

The public DMG remains self-contained: drag `Yulu.app` to `/Applications` and
launch it there. Grok CLI-compatible OAuth and explicit API-key alternatives
are unchanged. Recording Processing ends with transcript and summary; Share
remains manual-only with a fresh confirmation.

RC13 assets, tags, and partial acceptance evidence are preserved. This is a
prerelease, not completed installed-product acceptance. The collector and
candidate must come from the same clean source. macOS 13 remains the deployment
target, not a formal acceptance environment; required real-install journeys
run on macOS 14+ arm64. Stable `v0.23.0` remains gated on #170 accepting this
exact RC14 source, followed by the separate stable publication and RC-to-stable
update checks in #171.
